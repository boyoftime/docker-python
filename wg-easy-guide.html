Part 1: Setting Up WG-Easy with Docker

WG-Easy is a fantastic self-hosted WireGuard VPN server. There are two common versions available. Please choose ONE of the options below.

Step 1: Create the Project Directory

Regardless of which version you choose, start by creating a folder:

# Create a dedicated directory
mkdir /root/docker-deployment/wg-easy
cd /root/docker-deployment/wg-easy

Step 2: Create the `docker-compose.yml` File

Create the file:

nano docker-compose.yml

Now, copy the code from ONE of the options below:

OPTION A: LATEST VERSION (v15+) - RECOMMENDED

v15 configures almost everything through a first-run web setup wizard instead of environment variables. To skip that wizard and pre-fill it non-interactively (useful for scripted deployments), v15 supports a distinct set of INIT_* variables — these only apply on the very first container start. Data is stored locally in this folder.

services:
  wg-easy:
    # Uses the new official image repository
    image: ghcr.io/wg-easy/wg-easy:15
    container_name: wg-easy
    environment:
      # --- UNATTENDED SETUP (only read on first boot) ---
      - INIT_ENABLED=true
      - INIT_USERNAME=admin
      - INIT_PASSWORD=YOUR_STRONG_PASSWORD
      - INIT_HOST=YOUR_IP_OR_DOMAIN
      - INIT_PORT=51820
      - INIT_DNS=1.1.1.1,1.0.0.1
      - INIT_IPV4_CIDR=10.8.0.0/24
      - INIT_IPV6_CIDR=fd00:0::/64

    volumes:
      # Stores config files IN THIS DIRECTORY (as requested)
      - .:/etc/wireguard
      # Required for v15+ networking
      - /lib/modules:/lib/modules:ro

    ports:
      - "51820:51820/udp" # VPN Port
      - "51821:51821/tcp" # Web UI Port

    restart: unless-stopped
    cap_add:
      - NET_ADMIN
      - SYS_MODULE
    sysctls:
      - net.ipv4.conf.all.src_valid_mark=1
      - net.ipv4.ip_forward=1
      - net.ipv6.conf.all.disable_ipv6=0
      - net.ipv6.conf.all.forwarding=1
      - net.ipv6.conf.default.forwarding=1

    networks:
      - nginx-proxy

networks:
  nginx-proxy:
    external: true

Security note: INIT_* variables are only read once, on first startup. After you've confirmed login works, remove these lines from the file entirely — leaving INIT_PASSWORD sitting in plain text serves no purpose once setup is done, and only adds needless exposure.

IPv4/IPv6 CIDR pairing: INIT_IPV4_CIDR and INIT_IPV6_CIDR are a linked pair — if you set one, you must set both, or the container will fail validation.

OPTION B: STABLE VERSION (v14)

Use this if you want the older, simpler env-var setup instead of v15's setup wizard. This uses the maintained v14 release.

Don't use the weejewel/wg-easy image. That was the original Docker Hub repository, but the project has officially moved: Docker Hub's own page for it now reads "Moved to GitHub Container Registry — the new Docker URL is now ghcr.io/wg-easy/wg-easy." It's no longer maintained. Use ghcr.io/wg-easy/wg-easy:14 below instead.

Step B1: Generate a bcrypt password hash

v14 requires the Web UI password as a bcrypt hash, not plain text. Generate it with wg-easy's own image (run this on your VPS, in the same folder):

docker run --rm -it ghcr.io/wg-easy/wg-easy:14 wgpw 'YOUR_STRONG_PASSWORD'

This prints something like:

PASSWORD_HASH='$2a$12$abcdefghijklmnopqrstuv.wxyzABCDEFGHIJKLMNOPQRSTUVWXYZ'

Escaping $ for docker-compose: Copy the hash, but before pasting it into docker-compose.yml, replace every single $ with $$. Compose treats a lone $ as the start of a variable reference and will silently strip it otherwise — the same issue that affects any password containing a literal $ character.

So $2a$12$abc... becomes $$2a$$12$$abc... in the file below.

Step B2: The compose file

services:
  wg-easy:
    # The maintained v14 release
    image: ghcr.io/wg-easy/wg-easy:14
    container_name: wg-easy
    environment:
      # --- REQUIRED VARIABLES ---
      - WG_HOST=YOUR_SERVER_IP
      - PASSWORD_HASH=YOUR_ESCAPED_BCRYPT_HASH

      # --- CONFIGURATION ---
      - WG_PORT=51820
      - WG_DEFAULT_DNS=1.1.1.1,1.0.0.1

    volumes:
      # Stores config files in the same directory as this docker-compose file
      - .:/etc/wireguard

    ports:
      - "51820:51820/udp"
      - "51821:51821/tcp"
    
    restart: unless-stopped
    cap_add:
      - NET_ADMIN
      - SYS_MODULE
    sysctls:
      - net.ipv4.conf.all.src_valid_mark=1
      - net.ipv4.ip_forward=1

    networks:
      - nginx-proxy

networks:
  nginx-proxy:
    external: true

Step 3: Launch WG-Easy

⚠️ If you get a "Migration" Error (e.g. "invalid Configuration"):

If you see an error in the logs about migration, it means you have an old incompatible configuration file in this folder.

To fix this, you must delete the old file to start fresh:

rm /root/docker-deployment/wg-easy/config.json
rm /root/docker-deployment/wg-easy/wg0.json

Start the server normally:

cd /root/docker-deployment/wg-easy
docker compose up -d

⚠️ v15 only: "Invalid username or password" even though it's correct

INIT_* variables are only read on the very first container start against an empty data folder. If you change INIT_USERNAME or INIT_PASSWORD in the file afterward and run docker compose up -d or --force-recreate again, those changes are silently ignored — the logs will show Database Setting up already done. Skiping initial setup. instead of actually creating a new user. Recreating the container doesn't help, because the "setup complete" flag lives in the persisted data folder, not inside the container itself.

The fix is to wipe the data folder and start fresh exactly once, with your final values already correct in the file before that first start:

cd /root/docker-deployment/wg-easy
docker compose down
cd ..
rm -rf wg-easy
mkdir wg-easy
cd wg-easy
nano docker-compose.yml
# Paste your compose file with the FINAL values you want, then save.
docker compose up -d

Confirm it actually applied this time by checking the logs immediately after:

docker compose logs

You want to see lines like Creating initial user... and Setting initial host and port... — not Setup already done. Once you see the right lines, don't run up or --force-recreate again unless you intend to wipe the folder once more; any password changes after this point need the same wipe-and-restart process.

Part 2: Using the Web UI

  1. Access the UI by navigating to http://YOUR_SERVER_IP:51821 in your browser.
  2. Log in with the password you set in the config file.
  3. Click the "+ New Client" button to create your first VPN user.
  4. To connect a device, use one of the icons:
    • QR Code Icon: Best for mobile phones. Scan it with the WireGuard app.
    • Download Icon: Best for computers. This saves a .conf file.

v15 only: "You can't log in with an insecure connection. Use HTTPS."

Unlike v14, v15 refuses to log in at all over plain http:// — even for local testing directly against the IP and port. If you're just testing before setting up Nginx Proxy Manager (Part 5), add INSECURE=true to the environment: block and run docker compose up -d --force-recreate. Treat this as temporary: once you're accessing the panel through NPM over real HTTPS, remove INSECURE=true again.

Part 3: Customizing Client Configurations

You can manually edit the downloaded .conf file in a text editor for advanced customization.

Important: Setting the Correct VPN Endpoint

The Endpoint = ... line in your client config files is automatically generated from whichever host value you set — INIT_HOST on v15 (only on first boot; changeable afterward in Settings), or WG_HOST on v14.

The domain you use for the Web UI (via Nginx Proxy Manager) CANNOT be used for the VPN endpoint unless you open UDP ports on that specific domain.

Your Public URL variable should be:

  • Option 1: Your server's IP address (e.g., https://123.45.67.89).
  • Option 2: A separate DNS 'A' record (e.g., https://wg.yourdomain.com) pointing directly to the IP.

Part 4: Ongoing Management

Updating

cd /root/docker-deployment/wg-easy
docker compose pull
docker compose up -d

Uninstalling

cd /root/docker-deployment/wg-easy
docker compose down
cd ..
rm -rf wg-easy

Part 5: Securing the UI with Nginx Proxy Manager

Secure the admin panel (TCP port 51821) using SSL.

  1. Point a subdomain (e.g., `vpn.yourdomain.com`) to your server's IP.
  2. In Nginx Proxy Manager, add a new Proxy Host.
  3. Details Tab:
    • Domain Names: `vpn.yourdomain.com`
    • Forward Hostname / IP: `wg-easy`
    • Forward Port: `51821`
  4. SSL Tab: Request a new SSL certificate and turn on "Force SSL".

v15 users: once you're logging in through your NPM domain over real HTTPS, remove the temporary INSECURE=true line from Part 1 and recreate the container (docker compose up -d --force-recreate) — it's no longer needed and shouldn't be left on permanently.
