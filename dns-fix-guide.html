DNS Resolution Fix for Docker & API Connectivity

Fixing Docker Build Timeouts and Outgoing API Failures on Your VPS

Table of Contents

  • The Problem
  • The Root Cause
  • The Fix: Switch to Cloudflare DNS
  • Making It Permanent

The Problem

You may encounter one or both of these issues on your VPS:

  • Docker builds fail with the error: dial tcp: lookup registry-1.docker.io: i/o timeout
  • Outgoing API calls (e.g., to payment gateways like ClickPesa) intermittently fail with "unable to complete request"

Both symptoms point to the same underlying issue: the server cannot reliably resolve domain names to IP addresses.

The Root Cause

The default DNS resolver on most Ubuntu VPS instances is systemd-resolved, which listens at 127.0.0.53. When this local resolver is misconfigured or unresponsive, any process that needs to look up a domain name (Docker pulling images, your Flask app calling an external API) will time out or fail.

How to confirm this is your issue: Check what DNS server your system is currently using. If it shows 127.0.0.53 and you're experiencing the errors above, this is the problem.

# Check current DNS configuration
cat /etc/resolv.conf

If the output shows nameserver 127.0.0.53, that's the local systemd-resolved stub — and it's the source of your issues.

The Fix: Switch to Cloudflare DNS

The solution is to bypass the broken local resolver and point your server directly at a fast, reliable public DNS. Cloudflare's 1.1.1.1 is the fastest public DNS available.

Step 1: Switch DNS to Cloudflare

# Switch to Cloudflare DNS (fastest public DNS)
echo "nameserver 1.1.1.1" | sudo tee /etc/resolv.conf

Alternative: If you prefer Google's DNS instead, use 8.8.8.8:

# Alternative: Google DNS
echo "nameserver 8.8.8.8" | sudo tee /etc/resolv.conf

Step 2: Verify the Change

# Verify the change
cat /etc/resolv.conf

You should now see nameserver 1.1.1.1 (or 8.8.8.8) in the output.

Step 3: Rebuild and Restart Your Containers

With DNS now working, rebuild your Docker containers:

# Rebuild and restart containers
docker compose up --build -d

Docker should now be able to pull images and your API calls should resolve correctly.

Making It Permanent

The change above will revert after a reboot if systemd-resolved is still active — it will overwrite /etc/resolv.conf on startup. To make the fix permanent, you need to disable systemd-resolved entirely.

Step 1: Disable and Stop systemd-resolved

# Disable systemd-resolved so it doesn't start on boot
sudo systemctl disable systemd-resolved

# Stop the currently running service
sudo systemctl stop systemd-resolved

Step 2: Set Permanent DNS

# Set permanent DNS
echo "nameserver 1.1.1.1" | sudo tee /etc/resolv.conf

That's it! With systemd-resolved disabled and /etc/resolv.conf pointing to Cloudflare, your DNS will survive reboots and your Docker builds and API calls will work reliably.
