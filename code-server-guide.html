Why Code-Server?

Code-Server runs Visual Studio Code on your remote server. This setup allows you to:

  • Code from any device (iPad, Laptop, Phone).
  • Use your server's powerful resources (CPU/RAM).
  • Run Python scripts interactively using the built-in terminal.

Part 1: Installation with Docker

We will set up Code-Server with persistent storage for your settings and your code.

Step 1: Create the Project Directory

# Create directory for Code-Server
mkdir -p /root/docker-deployment/code-server
cd /root/docker-deployment/code-server

# Create a workspace folder for your code
mkdir workspace

Step 2: Create the `docker-compose.yml` File

nano docker-compose.yml

Paste the configuration below. Note the new DNS section—this is critical for installing tools like `uv` later.

services:
  code-server:
    image: lscr.io/linuxserver/code-server:latest
    container_name: code-server
    environment:
      - PUID=1000
      - PGID=1000
      - TZ=Etc/UTC

      # --- ACCESS SECURITY ---
      # This is the password you type in your BROWSER to log in to the IDE.
      - PASSWORD=your_secure_login_password
      
      # --- TERMINAL SECURITY ---
      # This is the password you type in the TERMINAL if you run 'sudo' commands.
      - SUDO_PASSWORD=your_sudo_root_password
      
      # Optional: Helps with proxy handling if you run web Apps
      #you can remove it if u want vs code to create localhost link automatically
      - PROXY_DOMAIN=code.yourdomain.com

    volumes:
      # Stores VS Code settings, extensions, and themes
      - ./config:/config
      # Stores your actual code projects
      - ./workspace:/config/workspace
    
    # CRITICAL: Fixes "Could not resolve host" errors when installing tools
    dns:
      - 8.8.8.8
      - 1.1.1.1

    ports:
      - 8443:8443
    restart: unless-stopped
    networks:
      - nginx-proxy

networks:
  nginx-proxy:
    external: true

Step 3: Launch Code-Server

docker compose up -d

Part 2: Securing with Nginx Proxy Manager

To use Code-Server securely, we must use HTTPS via Nginx Proxy Manager.

  1. Point a Subdomain: Create an 'A' record for `code.yourdomain.com` pointing to your server IP.
  2. Log in to Nginx Proxy Manager.
  3. Add Proxy Host:
    • Domain Names: `code.yourdomain.com`
    • Scheme http
    • Forward Hostname / IP: `code-server`
    • Forward Port: `8443`
    • CRITICAL: Turn on "Websockets Support".
  4. SSL Tab: Request a new SSL Certificate & Force SSL.

Part 3: Python Setup Masterclass (The `uv` Method)

By default, the environment is bare. We will use uv (a super-fast Python tool) to install Python 3.12.10 and manage dependencies.

Perform these steps inside the VS Code Terminal (Ctrl + `), NOT your VPS SSH terminal.

Step 1: One-Time System Fix (Important!)

The default Docker image has a setting that conflicts with `uv`. Run this block once to fix it permanently.

# 1. Add uv to the permanent path
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc

# 2. Fix the error by unsetting the broken system variable
echo 'unset VIRTUAL_ENV' >> ~/.bashrc

# 3. Reload the shell settings immediately
source ~/.bashrc

Step 2: Install `uv`

curl -LsSf https://astral.sh/uv/install.sh | sh
source $HOME/.local/bin/env

Verify it works by typing uv --version.

Step 3: Choose Your Workflow

How do you want to use Python? Choose Option A or Option B.

Option A: "Global" Environment (Easy Mode)

Best if you just want to run scripts without setting up a folder every time.

# 1. Create a main environment with Python 3.12.10
cd ~
uv venv my_global_env --python 3.12.10

# 2. Make it auto-activate every time you open a terminal
echo 'source ~/my_global_env/bin/activate' >> ~/.bashrc
source ~/.bashrc

# 3. Install packages globally
uv pip install flask pandas numpy

Step 4: Configure VS Code to "See" Python

VS Code needs to know exactly where your new Python is located so the "Play" button works.

  1. Open a Python file (e.g., app.py).
  2. Press F1 or Ctrl+Shift+P to open the Command Palette.
  3. Type and select: Python: Select Interpreter.
  4. Select "Enter interpreter path...".
  5. Paste one of these paths (they point to the same place):
    • ~/my_global_env/bin/python (Short format)
    • /config/my_global_env/bin/python (Absolute path)
  6. Press Enter. VS Code will now load this Python version automatically.

Pro Tip: Find your path automatically
If you are ever unsure where your Python is installed, simply type which python in the terminal.

It will return the exact path, for example: /config/my_global_env/bin/python.
You can copy this path and use it in the "Enter interpreter path" box.

Option B: Project-Specific Environment (Pro Mode)

Best for real projects (like `workspace`) to keep dependencies isolated.

# 1. Go to your project folder
cd /config/workspace

# 2. Create a fresh environment just for this folder
uv venv .venv --python 3.12.10

# 3. Activate it
source .venv/bin/activate

# 4. Install packages just for this project
uv pip install flask

Part 4: Managing Environments (Activate/Deactivate)

How to "Deactivate" Temporarily

If you want to exit the Python environment for just this session:

deactivate

Your prompt will lose the `(my_global_env)` prefix.

How to "Deactivate" Permanently

If you used Option A (Global Auto-Start) and want to stop it:

  1. Open the configuration file: nano ~/.bashrc
  2. Scroll to the bottom and find: source ~/my_global_env/bin/activate
  3. Add a # in front of it to comment it out: # source ...
  4. Save (Ctrl+X, Y, Enter) and restart your terminal.

About `which python`

If you are confused about which Python you are running, type:

which python
  • If it says /config/my_global_env/... -> You are using your custom Python 3.12.
  • If it says /usr/bin/python -> You are using the old system Python (Avoid this!).

Part 5: Previewing Your Apps (The "Ports" Tab)

When you run a Flask app (`python app.py`), you want to see it in your browser.

Do NOT use public domains for development testing. It exposes your work to the world and requires complex setup.

The Easy Way (Private Preview)

  1. Run your app in the terminal: python app.py
  2. Look at the panel at the bottom of VS Code (where Terminal is).
  3. Click the PORTS tab.
  4. You will see Port 5000 listed there.
  5. Click the Globe Icon 🌐 next to it.

This opens a secure, private tunnel to your app. Only you can see it.

Part 6: Advanced Public Previews (Subdomains)

If you want to share a running app with a friend (e.g., https://5000.code.yourdomain.com) without asking them for a password, or if you want to test custom subdomains, follow this setup.

remove this - PASSWORD=your_secure_login_password if you do not want user to be asked for a password when logging in

1. Enable the Variable

In your docker-compose.yml, ensure this line is active (uncommented):

environment:
  - PROXY_DOMAIN=code.yourdomain.com

(Replace with your actual domain).

2. Configure DNS

Go to your DNS provider (Namecheap/Cloudflare) and add a record for the specific port you want to expose (e.g., 5000).

  • Type: A Record
  • Host: 5000.code (Results in 5000.code.yourdomain.com)
  • Value: Your Server IP

3. Configure Nginx Proxy Manager

This is the trick: You must point the subdomain to Code-Server (8443), NOT the app port (5000). Code-Server handles the internal routing.

  1. Add Proxy Host:
    • Domain Name: 5000.code.yourdomain.com
    • Forward Hostname/IP: code-server
    • Forward Port: 8443 (Keep this as 8443!)
    • Websockets: Enabled.
  2. SSL: Request Certificate & Force SSL.

Now, when you visit https://5000.code.yourdomain.com, Code-Server will see you are requesting port 5000 and automatically route you to your running Python app.

Part 7: Deploying to Public (The Real Way)

When you are ready to share your app with friends without asking for a password, do NOT use VS Code.

Deploy it as a real Docker container.

  1. Create a `Dockerfile` in your project folder.
  2. Create a new `docker-compose.yml` for your app.
  3. Run it: `docker compose up -d`
  4. Go to Nginx Proxy Manager and point `app.yourdomain.com` to your new container.

(See the main Docker Guide for full deployment steps).

Part 8: Decommissioning

To remove Code-Server completely:

# 1. Remove Proxy Host in NPM.

# 2. Stop and remove containers and data
cd /root/docker-deployment/code-server
docker compose down -v

# 3. Remove directory (WARNING: Deletes your code in the workspace folder!)
cd ..
rm -rf code-server

Part 9: Troubleshooting Permissions (EACCES Error)

If you try to move or edit files created by another program (like FileBrowser) and get an error saying: Error: EACCES: permission denied, it is because of a user conflict.

FileBrowser usually runs as Root, while VS Code runs as a Standard User. The Standard User cannot touch the Root's files.

Option A: The Quick Fix (Recommended)

You can fix this instantly inside the VS Code terminal without restarting anything.

  1. Open the terminal in VS Code (Ctrl + `).
  2. Run this command to claim ownership of all files:
sudo chown -R abc:abc /config/workspace

(Enter your sudo password when prompted).

Option B: The "God Mode" Fix (Run as Root)

If you never want to deal with permissions again, you can force VS Code to run as Root (Administrator). This gives it full access to everything.

  1. Edit your docker-compose.yml file.
  2. Change the User IDs to 0:
    environment:
      - PUID=0  # 0 = Root User
      - PGID=0  # 0 = Root Group
  1. Restart the container: docker compose up -d

Cleanup Tip:
After switching to Root, your files on the server might still be tagged as "User 1000". While Root can access them fine, it is good practice to update their ownership to match the new setting.

Run this on your VPS terminal:
chown -R root:root /root/docker-deployment/code-server/config

Part X: Public Sharing (Safe Mode) Using a Separate “Share Port”

This method keeps your default development ports 5000 (Flask) and 5500 (Live Server) PRIVATE. You will only expose a separate internal “share port” when you want to show your project to a friend.

Our Safe Port Plan (Recommended)
5000 = Private Flask (default)
5500 = Private Live Server (default)
5001 = Share Internal Port (only when you want to share)
15555 = Public Test Port (used in Nginx Proxy Manager)

Step 1: Expose ONLY the Public Test Port (15555) → Share Port (5001)

Edit your code-server docker-compose.yml and add this port mapping.

services:
            code-server:
                # ...
                ports:
                - "8443:8443"         # #comment code-server (password protected)
                - "15555:5001"        # #comment PUBLIC test port -> internal SHARE port (5001 only)

Restart the container:

# #comment run on VPS
            cd /root/docker-deployment/code-server
            docker compose down
            docker compose up -d

Important:
Your default ports 5000 and 5500 are NOT exposed publicly by this setup.
Only whatever runs on 5001 can be shared.

Step 2: DNS Example (Create a Public Test Subdomain)

Go to your DNS provider (Cloudflare/Namecheap) and create an A record like this:

  • Type: A
  • Name/Host: test
  • Value: Your VPS Public IP
  • TTL: Auto

This gives you:

test.yourdomain.com

Step 3: Nginx Proxy Manager (Point test.yourdomain.com to Port 15555)

  1. Add Proxy Host
  2. Domain Names: test.yourdomain.com
  3. Scheme: http
  4. Forward Hostname / IP: Your VPS IP (example: 123.123.123.123)
  5. Forward Port: 15555
  6. Websockets: ON (safe to enable)
  7. SSL Tab: Request Certificate + Force SSL

Now, your friend will open:

https://test.yourdomain.com

What will your friend see?
They will see ONLY the app running on the internal share port 5001.
If nothing is running on 5001, the page will not load.

Step 4A: Sharing a Flask App (Switch from Private 5000 → Share 5001)

By default, many Flask apps run like this: app.run(host='0.0.0.0', port=5000) (PRIVATE). When you want to share, change ONLY the port to 5001.

Find this at the bottom of your Flask file (example: app.py):

# #comment PRIVATE MODE (default)
            if __name__ == "__main__":
                app.run(host="0.0.0.0", port=5000)

Change to this ONLY when you want to share publicly:

# #comment SHARE MODE (public via test.yourdomain.com)
            if __name__ == "__main__":
                app.run(host="0.0.0.0", port=5001)

Result:
- Private testing stays on 5000
- Public sharing uses 5001 → mapped to public port 15555 → https://test.yourdomain.com

Step 4B: Sharing a Static Website (No Flask) Without Touching Live Server

If you don’t want to change Live Server settings, you can share your HTML folder using Python’s built-in server on the SHARE port 5001. 

# #comment go to your project folder
            cd /config/workspace/your-project

            # #comment SHARE MODE: serve this folder on port 5001
            python3 -m http.server 5001 --bind 0.0.0.0

Your friend opens:

https://test.yourdomain.com

To stop sharing, press CTRL + C in the terminal.

Step 4C: (Optional) If You Want Live Server Itself to Use 5001

Live Server default is usually 5500. If you want Live Server to run on 5001 (your SHARE port), you can set it from Remote Settings (recommended in code-server).

  1. Press Ctrl + Shift + P
  2. Type: Preferences: Open Remote Settings (JSON)
  3. Add this setting (example):
{
            "liveServer.settings.port": 5001
            }

How to switch back to Private (disable Live Server sharing)
Open the same Remote Settings JSON and either:
1) Change it back to 5500, or
2) Remove the line: "liveServer.settings.port": 5001

Step 5: Disable Public Sharing (Go Back to Private Mode)

When you finish sharing, remove the public route completely:

  1. In Nginx Proxy Manager: delete the Proxy Host for test.yourdomain.com
  2. In DNS: optionally delete the A record test
  3. In docker-compose.yml: remove the mapping line "15555:5001"
  4. Restart:
# #comment apply changes
            cd /root/docker-deployment/code-server
            docker compose up -d

Security Warning:
Anything exposed via test.yourdomain.com is public to anyone who has the link. Only enable sharing when needed, and disable it when done.
