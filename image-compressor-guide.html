Setting Up a Self-Hosted Image Compressor

Optimize your images privately without 3rd party services.

Why Host Your Own Compressor?

Online image compression tools are convenient, but they often have file size limits, require uploads to unknown servers, or bombard you with ads.

Hosting your own lightweight compressor (`imgcompress`) gives you:

  • Privacy: Images never leave your server.
  • Speed: No upload limits or queues.
  • Simplicity: A clean interface with no distractions.

Part 1: Installation with Docker

We will set up the compressor in a dedicated folder. We will use host port 3001 to avoid conflicts with your other services.

Step 1: Create the Project Directory

# Create directory for the compressor
mkdir -p /root/docker-deployment/imgcompress
cd /root/docker-deployment/imgcompress

Step 2: Create the `docker-compose.yml` File

nano docker-compose.yml

Paste the following configuration. We have added the nginx-proxy network to ensure it fits into your existing infrastructure.

services:
  imgcompress:
    image: karimz1/imgcompress:latest
    container_name: imgcompress
    restart: always
    ports:
      # Maps host port 3001 to container port 5000
      - "3001:5000"
    environment:
      # Set to true to remove the mascot and enable a minimal UI
      - DISABLE_LOGO=false
      # Set to true to hide the history of compressed files (Good for public use)
      - DISABLE_STORAGE_MANAGEMENT=false
    networks:
      - nginx-proxy

# Connect to your existing shared network
networks:
  nginx-proxy:
    external: true

Step 3: Launch the Service

docker compose up -d

You can verify it is running by checking http://YOUR_SERVER_IP:3001 (if you allowed port 3001 in your firewall).

Part 2: Configuration Options

You can customize the look and functionality using the environment variables in your docker-compose.yml file.

DISABLE_LOGO

  • false (Default): Shows the friendly mascot character.
  • true: Removes the mascot for a purely utilitarian, professional look.

DISABLE_STORAGE_MANAGEMENT

  • false (Default): Users can see a list of recently compressed files and download them again later.
  • true: Disables the "history" view. This is recommended if multiple people use this tool and you want privacy between users.

To apply changes, simply edit the file and run docker compose up -d again.

Part 3: Securing with Nginx Proxy Manager

Now, let's give it a domain name (e.g., compress.yourdomain.com) and SSL.

  1. Point a Subdomain: In your domain registrar, create an 'A' record for compress.yourdomain.com pointing to your server IP.
  2. Log in to Nginx Proxy Manager.
  3. Add Proxy Host:
    • Domain Names: compress.yourdomain.com
    • Forward Hostname / IP: imgcompress (This matches the container name).
    • Forward Port: 5000 (This is the internal port inside the container).
    • Websockets Support: Enabled (Optional, but good practice).
  4. SSL Tab: Request a new SSL Certificate and Force SSL.

Your tool is now live at https://compress.yourdomain.com!

Part 4: Decommissioning

To remove the image compressor tool:

# 1. Remove Proxy Host in NPM.

# 2. Stop and remove containers
cd /root/docker-deployment/imgcompress
docker compose down

# 3. Remove directory
cd ..
rm -rf imgcompress
