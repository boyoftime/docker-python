Why MinIO Instead of Uploading Straight to the Server?

When a Flask app saves uploads to its own disk, every single byte has to travel through Flask. A teacher uploading a 300 MB lecture video ties up a worker for minutes, and nginx blocks it anyway because of client_max_body_size. Videos then play badly, because Flask is not built to stream large files.

MinIO is your own private file storage server (an "S3-compatible object store"). It runs as one more Docker container on your VPS and changes the picture completely:

  • Files never pass through Flask. The browser uploads directly to MinIO using a temporary signed link that Flask generates. Flask only records the file name in MySQL.
  • No upload size limit. We set client_max_body_size 0; on MinIO's own proxy host only — your app keeps its safe, small limit.
  • Videos stream properly. MinIO supports range requests, so viewers can skip and seek instantly instead of downloading the whole file first.
  • Files stay private. Buckets are private by default. Your app hands out links that expire, so only signed-in users can view.
  • One install serves every project. Each app gets its own bucket and its own keys.

Vocabulary in one line: a bucket is like a top-level folder for one app; an object is a file inside it; an access key + secret key is the username and password your app uses to talk to MinIO.

Part 1: Installation with Docker

Step 1: Check Your Free Ports

MinIO wants ports 9000 and 9001, but 9000 is already used by the Portainer Agent on this server. Check the Server Port Registry and pick free ones. This guide uses 9002 and 9003.

Step 2: Create the Project Directory

mkdir -p /root/docker-deployment/minio
cd /root/docker-deployment/minio

Step 3: Create the `docker-compose.yml` File

nano /root/docker-deployment/minio/docker-compose.yml

Paste the following. Change the password to something strong and unique — this is the master login for all your files.

services:
  minio:
    image: minio/minio:latest
    container_name: minio
    restart: always
    command: server /data --console-address ":9001"
    environment:
      MINIO_ROOT_USER: someless
      MINIO_ROOT_PASSWORD: your-strong-password-here
    ports:
      - "9002:9000"   # S3 API — apps and browsers talk to this
      - "9003:9001"   # Web console — the admin GUI
    volumes:
      - ./data:/data
    networks:
      - nginx-proxy

networks:
  nginx-proxy:
    external: true

Step 4: Start It

docker compose up -d

Open http://YOUR_SERVER_IP:9003 in a browser. You should see the MinIO login page. Sign in with the root user and password you just set.

Why nginx-proxy network? It puts MinIO on the same Docker network as Nginx Proxy Manager, so NPM can reach it by container name (minio) in the next part — no IP addresses needed.

Part 2: Securing It with Nginx Proxy Manager

MinIO is really two services in one container, so it needs two subdomains: one for the API (what apps use) and one for the console (what you use). This guide uses:

DomainPoints toUsed by
miniofiles.someless.topport 9000 (S3 API)Your Flask apps, students' browsers
minio.someless.topport 9001 (console)Only you, for administration

Step 1: Create the DNS Records

At your DNS provider, add two A records pointing to your server's IP address:

  • miniofiles → YOUR_SERVER_IP
  • minio → YOUR_SERVER_IP

Wait two or three minutes before continuing — Let's Encrypt must be able to find these domains, or the certificate request fails with "Internal Error".

Step 2: Proxy Host for the Console

In Nginx Proxy Manager, click Add Proxy Host:

FieldValue
Domain Namesminio.someless.top
Schemehttp
Forward Hostname / IPminio
Forward Port9001
Websockets SupportON (the console needs it)
SSL tabRequest a new SSL Certificate, Force SSL ON, HTTP/2 ON

Step 3: Proxy Host for the API

Add a second proxy host:

FieldValue
Domain Namesminiofiles.someless.top
Schemehttp
Forward Hostname / IPminio
Forward Port9000
Websockets SupportOFF
SSL tabRequest a new SSL Certificate, Force SSL ON, HTTP/2 ON

Then open the gear icon (Advanced) tab and paste this. This is the part that removes the upload size limit:

client_max_body_size 0;
proxy_request_buffering off;
proxy_read_timeout 3600s;
proxy_send_timeout 3600s;

client_max_body_size 0 means unlimited, and proxy_request_buffering off makes nginx stream the upload straight through instead of saving it to disk first.

Step 4: Tell MinIO Its Public Addresses

MinIO must know its own public URLs, or the console will misbehave and the temporary file links it generates will contain an internal address that nobody can reach.

nano /root/docker-deployment/minio/docker-compose.yml

Add the two MINIO_..._URL lines to the environment section:

    environment:
      MINIO_ROOT_USER: someless
      MINIO_ROOT_PASSWORD: your-strong-password-here
      MINIO_SERVER_URL: https://miniofiles.someless.top
      MINIO_BROWSER_REDIRECT_URL: https://minio.someless.top

Apply it:

cd /root/docker-deployment/minio
docker compose up -d

Step 5: Test

  • https://minio.someless.top → the login page, with a padlock.
  • https://miniofiles.someless.top → a short XML "AccessDenied" page. That is correct — it means the API answered and refused anonymous access, exactly as it should.

Optional — close the raw ports. Once both domains work, you can delete the whole ports: section from the compose file and run docker compose up -d again. NPM still reaches MinIO over the Docker network, but IP:9002 and IP:9003 disappear from the public internet. Keep the ports only if you want a backup entrance.

Part 3: Creating a Bucket for Your App

Each app gets one bucket. Do this in the console at https://minio.someless.top:

  1. Click Create Bucket in the left menu.
  2. Type a name — lowercase letters, numbers and hyphens only. Example: online-elearning.
  3. Leave Versioning, Object Locking and Quota off.
  4. Click Create Bucket.

The bucket is private by default. That is what you want: your app will hand out temporary signed links to the people who are allowed to view each file.

"Invalid bucket name"? The name must be 3–63 characters, lowercase, and cannot contain spaces, underscores or capital letters. You will also see this error if a bucket with that name already exists.

Part 4: Creating Access Keys for Your App

Never let your app log in with the root user. Instead create a service account — a key pair that can only touch one bucket. If it ever leaks, the rest of your files are untouched.

Note: the Community Edition console has no "Access Keys" screen, so we use MinIO's built-in mc command-line tool inside the container. Nothing extra to install.

Step 1: Connect the Admin Tool

Replace the password with your MinIO root password. Keep the single quotes — they protect any special characters.

docker exec minio mc alias set local http://localhost:9000 someless 'YOUR_ROOT_PASSWORD'

It should answer Added `local` successfully.

Step 2: Write the Policy

This policy is the fence: the key can read, write, delete and list — but only inside this one bucket. Change online-elearning to your bucket name in both places.

docker exec -i minio sh -c 'cat > /tmp/elearning-policy.json' <<'EOF'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject", "s3:DeleteObject", "s3:ListBucket"],
      "Resource": [
        "arn:aws:s3:::online-elearning",
        "arn:aws:s3:::online-elearning/*"
      ]
    }
  ]
}
EOF

Two lines are needed in Resource: the first is the bucket itself (for listing), the second with /* is every file inside it.

Step 3: Create the Keys

docker exec minio mc admin user svcacct add --policy /tmp/elearning-policy.json local someless

It prints something like:

Access Key: Z20JC4C9LNTS3SL2ND3E
Secret Key: 8FG5PwCwgNoHvYrjAz8LLYVl+7lxJZ5TdEw9+0z0
Expiration: no-expiry

Copy both immediately. The secret key is shown only once and can never be displayed again. If you lose it, you simply delete that key and create a new one (see Part 6). Treat it like a password: never in screenshots, never in a public git repository.

Useful: List the Keys You Have Created

docker exec minio mc admin user svcacct ls local someless

Part 5: Connecting Your Flask App

Step 1: Install the Library

Add to requirements.txt:

minio==7.2.15

Step 2: Put the Settings in `.env`

Never hard-code keys in your Python files. Put them in .env, which is already excluded from git and from the Docker image.

# MinIO object storage
MINIO_ENDPOINT=miniofiles.someless.top
MINIO_SECURE=true
MINIO_ACCESS_KEY=your-access-key
MINIO_SECRET_KEY=your-secret-key
MINIO_BUCKET=online-elearning

Note: the endpoint is the domain only — no https:// and no trailing slash. MINIO_SECURE=true is what tells the client to use HTTPS.

Step 3: Create the Client

import os
from minio import Minio

client = Minio(
    os.getenv('MINIO_ENDPOINT'),
    access_key=os.getenv('MINIO_ACCESS_KEY'),
    secret_key=os.getenv('MINIO_SECRET_KEY'),
    secure=os.getenv('MINIO_SECURE') == 'true',
    # Required: a bucket-scoped key is not allowed to ask MinIO for the
    # bucket's region, so we state it and skip that lookup entirely.
    region='us-east-1',
)

If you forget region, every upload fails with S3Error: AccessDenied even though the keys are correct. The client tries a "get bucket location" call first, which your tight policy rightly refuses. Setting the region skips that call.

Step 4: The Four Things You Will Actually Do

# 1. Upload a file from disk (server side)
client.fput_object('online-elearning', 'ilonga/materials/notes.pdf',
                   '/path/to/notes.pdf', content_type='application/pdf')

# 2. Give the browser a link to upload DIRECTLY to MinIO (never through Flask)
from datetime import timedelta
upload_url = client.presigned_put_object(
    'online-elearning', 'ilonga/materials/video.mp4', expires=timedelta(hours=1))

# 3. Give a signed-in student a link to WATCH or READ the file (expires)
view_url = client.presigned_get_object(
    'online-elearning', 'ilonga/materials/video.mp4', expires=timedelta(hours=2))

# 3b. Same file, but forced as a DOWNLOAD with a friendly filename
download_url = client.presigned_get_object(
    'online-elearning', 'ilonga/materials/notes.pdf', expires=timedelta(hours=2),
    response_headers={'response-content-disposition':
                      'attachment; filename="Week 1 Notes.pdf"'})

# 4. Delete a file
client.remove_object('online-elearning', 'ilonga/materials/notes.pdf')

The difference between "watch online" and "download" is only the response-content-disposition header: inline (the default) plays or displays the file, attachment saves it.

Step 5: Docker Compose — Pass the Settings In

If your app runs in Docker, it reads .env through env_file. Make sure the .env on the server has the MinIO lines too — the one on your PC is not the one the container reads.

Step 6: Quick Test From Your PC

A one-file test to prove the whole chain works before building any feature:

import os
from dotenv import load_dotenv
from minio import Minio

load_dotenv()
client = Minio(os.getenv('MINIO_ENDPOINT'),
               access_key=os.getenv('MINIO_ACCESS_KEY'),
               secret_key=os.getenv('MINIO_SECRET_KEY'),
               secure=True, region='us-east-1')

bucket = os.getenv('MINIO_BUCKET')
client.fput_object(bucket, 'test/hello.png', r'C:\Users\you\Downloads\hello.png')

for obj in client.list_objects(bucket, recursive=True):
    print(obj.object_name, obj.size, 'bytes')

Then refresh the bucket in the console — the file appears there.

Part 6: Rotating Keys (When a Secret Leaks)

If a secret key is ever exposed — pasted into a chat, committed to git, printed in a screenshot — do not panic. Rotating takes about ten seconds and nothing is lost: the files are untouched, only the login changes.

Step 1: See What Keys Exist

docker exec minio mc admin user svcacct ls local someless

Step 2: Create the Replacement First

Create the new key before deleting the old one, so your app is never without a working login.

docker exec minio mc admin user svcacct add --policy /tmp/elearning-policy.json local someless

Copy the new Access Key and Secret Key.

Lost /tmp/elearning-policy.json? The /tmp folder is wiped whenever the container restarts. Just re-run the policy command from Part 4, Step 2 before creating the key.

Step 3: Update the App

nano /root/docker-deployment/apps/YOUR_APP/.env     # paste the new keys
cd /root/docker-deployment/apps/YOUR_APP
docker compose up -d                                # restart so it reads them

Test that uploads still work.

Step 4: Delete the Old Key

docker exec minio mc admin user svcacct rm local OLD_ACCESS_KEY

The leaked key is now dead and useless to anyone who saw it.

Changing the Root Password

The root password is separate. To change it, edit MINIO_ROOT_PASSWORD in the compose file and run docker compose up -d. Service account keys keep working — they are independent of the root password.

Part 7: Adding a Second or Third App

You never install MinIO again. One MinIO serves every project on the server — each app just gets its own bucket and its own keys, and cannot see the others.

  1. Create a bucket in the console, e.g. bbr-files.
  2. Write a policy for it (same as Part 4 Step 2, with the new bucket name and a new file name): 
    docker exec -i minio sh -c 'cat > /tmp/bbr-policy.json' <<'EOF'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject", "s3:DeleteObject", "s3:ListBucket"],
      "Resource": [
        "arn:aws:s3:::bbr-files",
        "arn:aws:s3:::bbr-files/*"
      ]
    }
  ]
}
EOF
  3. Create its keys: 
    docker exec minio mc admin user svcacct add --policy /tmp/bbr-policy.json local someless
  4. Put those keys in that app's .env with MINIO_BUCKET=bbr-files.

Done. If app #2's key leaks, app #1's files are still completely safe.

Part 8: Where Files Live & How to Back Them Up

Everything is stored in the folder you mapped in the compose file:

/root/docker-deployment/minio/data/
└── online-elearning/          ← the bucket
    └── test/
        └── app.png/           ← each object is a FOLDER
            └── xl.meta        ← the real data + metadata

Look, but never touch. Objects are not stored as plain files — xl.meta is MinIO's internal format. Browsing with WinSCP is harmless, but never add, rename or delete anything inside this folder by hand: it corrupts the bucket's bookkeeping. Always go through the console, mc, or your app.

Backup — The Clean Way (No Downtime)

# Mirror the bucket into a normal folder you can copy anywhere
docker exec minio mc mirror local/online-elearning /data/backup-elearning

Backup — The Simple Way (Stop, Copy, Start)

cd /root/docker-deployment/minio
docker compose stop
tar czf minio-backup-$(date +%F).tar.gz data/
docker compose start

Add whichever you prefer to the same routine you use for your MySQL backups. MySQL holds the records; this folder holds the actual files — you need both.

Part 9: Troubleshooting

ProblemCause & Fix
S3Error: AccessDenied when uploading, though the keys are right The client asked for the bucket region and your scoped policy refused. Add region='us-east-1' to the Minio(...) client.
NPM says "Internal Error" when requesting the certificate The DNS A record does not exist yet or has not propagated. Add it, wait 2–3 minutes, save again.
Console loads but keeps logging you out / behaves strangely Websockets Support is off on the console's proxy host. Turn it on.
413 Request Entity Too Large on upload The Advanced config is missing on the API proxy host. Add client_max_body_size 0; (Part 2, Step 3).
File links point to localhost or an internal address MINIO_SERVER_URL is not set. Add it to the compose environment (Part 2, Step 4).
"Invalid bucket name" Use lowercase letters, numbers and hyphens only — or the bucket already exists.
mc: command not found Run it inside the container: every command starts with docker exec minio mc ...
Uploads cut off after ~60 seconds Proxy timeouts. Confirm proxy_read_timeout 3600s; and proxy_send_timeout 3600s; in the Advanced tab.

Useful Commands

# Is it running?
docker ps | grep minio

# What went wrong?
docker logs minio --tail 50

# List everything in a bucket
docker exec minio mc ls --recursive local/online-elearning

# How much space is used?
docker exec minio mc du local/online-elearning

# Delete one file
docker exec minio mc rm local/online-elearning/test/app.png

Part 10: Decommissioning MinIO

If you ever need to remove MinIO completely:

  1. Back up the files first — this is the only copy. 
    cd /root/docker-deployment/minio
tar czf ~/minio-final-backup.tar.gz data/
  2. Stop and remove the container: 
    cd /root/docker-deployment/minio
docker compose down
  3. Delete the project folder — this destroys every stored file permanently. 
    cd ..
rm -rf minio
  4. Delete the two proxy hosts in Nginx Proxy Manager, and the two DNS records.

MinIO has been completely removed from your server.
